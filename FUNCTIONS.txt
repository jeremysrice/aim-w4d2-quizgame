QUIZ CLASH: FUNCTION AND SECTION REFERENCE
==========================================

A plain-English guide to every section and function in the game's
JavaScript. For each function it describes what the function does and
where it could still break. The logic is split across four files:

  storage.js      Safe wrapper around browser storage
  game-logic.js   The game's rules, with no page code (config, building a
                  game, timing, scoring, results, leaderboard math)
  trivia-api.js   Live questions from the Open Trivia Database: fetching,
                  caching, the 30-minute refresh and cross-tab
                  coordination
  script.js       Page and display code: screens, buttons, timer
                  display, results and leaderboard

questions.js contains only the built-in backup questions (data), so it
isn't covered here. The tests in tests/ check game-logic.js, storage.js
and trivia-api.js; run them with "npm test".

LOAD ORDER MATTERS: the page must load storage.js, questions.js,
game-logic.js, trivia-api.js, then script.js. Each file uses things
defined in the files loaded before it.


======================================================================
FILE: storage.js
======================================================================

----------------------------------------------------------------------
SECTION: Safe storage (file overview)
----------------------------------------------------------------------
Every read and write of browser storage goes through this file, so
blocked or full storage can never crash the game. Values are saved as
JSON. If storage can't be used at all, it falls back to memory that
lasts until the page is closed.

createSafeStorage
  What it does:   Builds the storage wrapper. It tests the real storage
                  once by writing and removing a test key, then provides
                  get, set, remove and persistent (described below).
  Could break:    The test write happens on every page load. If storage
                  works at that moment but fills up later, persistent
                  still says true, so the setup screen won't show its
                  warning (the results screen still does, because set
                  reports the failure).

get (inside createSafeStorage)
  What it does:   Reads and parses a saved value. Returns a fallback if
                  it's missing, unreadable or corrupted. A newer copy
                  kept in memory (from a failed write) wins.
  Could break:    No known crash paths. Corrupted data is silently
                  replaced by the fallback, so it's never reported.

set (inside createSafeStorage)
  What it does:   Saves a value. Returns true if it was saved
                  permanently, or false if it could only be kept in
                  memory for this session.
  Could break:    Values that can't be turned into JSON (such as
                  circular objects) return false and are not kept at
                  all, even in memory.

remove (inside createSafeStorage)
  What it does:   Deletes a value from storage and from memory.
  Could break:    No known issues; errors are ignored.

persistent (inside createSafeStorage)
  What it does:   True if values survive closing the page, false if
                  they're memory-only.
  Could break:    See createSafeStorage: it can say true even though
                  later writes fail because storage is full.

safeStorage
  What it does:   The one shared storage wrapper used by the whole app,
                  backed by localStorage when available.
  Could break:    Memory-only data isn't shared between tabs, so with
                  storage blocked each tab has its own leaderboard.


======================================================================
FILE: game-logic.js
======================================================================

----------------------------------------------------------------------
SECTION: Config
----------------------------------------------------------------------
Points per difficulty, the order of difficulties, questions per game
length, the most players (2), the timer length, the size of the speed
bonus and the leaderboard size.

Where it could break:
  - If the time limit is set to 0, there's no time to answer, so every
    question times out (the bonus math is guarded and won't crash).
  - Raising a game length beyond what the question bank can supply
    doesn't crash any more, but games are quietly shortened.

----------------------------------------------------------------------
SECTION: Helpers
----------------------------------------------------------------------

shuffle
  What it does:   Returns a randomly reordered copy of a list. A custom
                  random function can be passed in, so tests get the
                  same order every time.
  Could break:    No known issues.

makeId
  What it does:   Creates a unique id for a leaderboard entry, using
                  the browser's crypto.randomUUID where allowed and a
                  time-plus-random fallback elsewhere.
  Could break:    The fallback (used on pages opened from disk) is very
                  unlikely to repeat, but isn't guaranteed unique.

----------------------------------------------------------------------
SECTION: Questions
----------------------------------------------------------------------

isValidQuestion
  What it does:   Checks a question is safe to play: non-empty text,
                  2-4 non-empty choices with no repeats (ignoring case
                  and spaces), and a valid correct-answer position.
  Could break:    Questions with more than 4 choices are rejected, even
                  if otherwise fine, because only A-D buttons exist.

buildQueue
  What it does:   Builds the list of questions for a game. It skips
                  broken questions, tops up a short difficulty from the
                  built-in questions, and shortens the game evenly if
                  there still aren't enough. Each player gets their own
                  questions from easy to hard, with choices shuffled by
                  position, and turns alternate.
  Could break:    - When a game is shortened, nothing tells the
                    players; it just has fewer questions.
                  - It only throws an error if there isn't even one
                    question per player for every difficulty.

----------------------------------------------------------------------
SECTION: Timing and scoring
----------------------------------------------------------------------

timeRemaining
  What it does:   Works out the seconds left on a question from the
                  real time that has passed since it appeared, kept
                  between 0 and the time limit.
  Could break:    Both times must come from the same clock. The app
                  uses performance.now(), which device clock changes
                  don't affect.

calculatePoints
  What it does:   Base points for the difficulty plus a speed bonus of
                  up to +50%. An unknown difficulty scores 0 instead of
                  NaN, and the time left is kept in range.
  Could break:    No known issues.

scoreAnswer
  What it does:   Scores one answer and reports whether it was correct,
                  whether it timed out, and the points earned. An answer
                  that arrives after time ran out counts as a timeout.
  Could break:    No known issues.

----------------------------------------------------------------------
SECTION: Players
----------------------------------------------------------------------

createPlayer
  What it does:   Creates a player with a zero score and empty stats
                  for each difficulty.
  Could break:    No known issues.

applyAnswer
  What it does:   Returns an updated copy of a player after one answer,
                  leaving the original unchanged.
  Could break:    A difficulty the player has no stats for is started
                  from zero instead of failing.

accuracy
  What it does:   The percentage of answered questions a player got
                  right.
  Could break:    No known issues.

decideResult
  What it does:   Picks the results title and the winner(s). For one
                  player: "New High Score!", "You Made the
                  Leaderboard!" or "Quiz Complete!". For several
                  players: "<name> Wins!" or "It's a Tie!".
  Could break:    With three or more players, a tie between only some
                  of them still says "It's a Tie!" without naming who.
                  The game currently allows only two players.

----------------------------------------------------------------------
SECTION: Leaderboard math
----------------------------------------------------------------------

isValidEntry
  What it does:   Checks a saved leaderboard entry has a text id and
                  name, a positive score and a date.
  Could break:    No known issues.

sortBoard
  What it does:   Returns a sorted copy: highest score first, and on a
                  tie, the more recent score ranks higher.
  Could break:    No known issues.

mergeLeaderboard
  What it does:   Adds a game's scores to the leaderboard, ignores
                  zeros, drops damaged old entries, keeps the top 5 and
                  reports which new entries made it.
  Could break:    All game lengths share one board, so Long games
                  (which can score about twice as much as Short ones)
                  crowd out the others.


======================================================================
FILE: trivia-api.js
======================================================================

----------------------------------------------------------------------
SECTION: Config
----------------------------------------------------------------------
All the settings in one object: the API address, the 30-minute refresh,
the 5-minute retry, the 1-minute wait when another tab is fetching, 20
questions per difficulty, the 5.5-second gap between requests, the
10-second request timeout, 3 attempts when rate-limited, the cache key
and version, and the name of the cross-tab lock.

Where it could break:
  - The 5.5-second gap assumes the API's current limit of one request
    every 5 seconds per IP address.

----------------------------------------------------------------------
SECTION: State
----------------------------------------------------------------------
The live-question status: the current questions, where they came
from, when they were fetched, when the next refresh is due, whether
this tab is fetching, the last error, whether the last refresh was
partial, and the functions to notify on changes.

Where it could break:
  - It's shared with script.js by name, so another script using the
    same name would overwrite it.

----------------------------------------------------------------------
SECTION: Helpers
----------------------------------------------------------------------

wait
  What it does:   Pauses for a given time, to space out API requests.
  Could break:    No known issues.

notifyQuestionListeners
  What it does:   Tells every registered function that the question
                  status changed. Each one runs separately, so one
                  failing can't stop the others.
  Could break:    No known issues; a failing listener is logged.

onQuestionSourceChange
  What it does:   Registers a function to call when the question status
                  changes. Registering the same function twice has no
                  effect.
  Could break:    There's no way to unregister a function.

getActiveBank
  What it does:   Returns the questions the next game should use: the
                  live set for each difficulty that has one, otherwise
                  the built-in set.
  Could break:    No known issues; buildQueue handles any shortfall.

----------------------------------------------------------------------
SECTION: Cache
----------------------------------------------------------------------

loadQuestionCache
  What it does:   Loads saved questions on page load. It ignores and
                  deletes caches that are corrupted, from an older
                  version, dated in the future, or have no playable
                  questions.
  Could break:    Changing the cache format means bumping the cache
                  version; forgetting to could load mismatched data
                  (broken questions are still filtered out).

saveQuestionCache
  What it does:   Saves the live questions. If storage is full or
                  blocked it only logs a warning, because the new
                  questions are already in use.
  Could break:    If saving fails, the next page load fetches again.

----------------------------------------------------------------------
SECTION: Fetching
----------------------------------------------------------------------

normalizeApiQuestion
  What it does:   Converts one API question into the game's format,
                  decoding its text and shortening category names.
                  Returns nothing for a question that can't be decoded
                  or isn't playable, so one bad question is skipped
                  instead of sinking the rest.
  Could break:    If the API renames its fields, every question is
                  skipped and the difficulty counts as failed.

fetchJsonWithTimeout
  What it does:   Fetches a web address and reads the reply, giving up
                  after the timeout. The timeout covers reading the
                  reply too.
  Could break:    No known issues.

fetchDifficulty
  What it does:   Fetches the questions for one difficulty. When
                  rate-limited, it waits (longer each time) and retries,
                  up to 3 attempts in total.
  Could break:    In the worst case (three slow replies that each
                  report a rate limit), one difficulty can take about 45
                  seconds before failing. A timeout isn't retried; it
                  fails that difficulty straight away.

fetchAllDifficulties
  What it does:   Fetches each difficulty in turn, 5.5 seconds apart.
                  A failure on one doesn't stop the others.
  Could break:    No known issues.

withRefreshLock
  What it does:   Uses the browser's Web Locks API so only one tab
                  refreshes at a time. Lock-free fetching is used in
                  older browsers, on pages opened from disk (where
                  Chrome's lock request never answers) and if the lock
                  request throws.
  Could break:    Coordination only works within one browser. Other
                  devices, or tabs of a local copy opened from disk,
                  can still hit the rate limit together.

refreshQuestions
  What it does:   Fetches a fresh set of questions. It first checks
                  whether another tab just refreshed (unless the button
                  forced it), keeps any difficulties that succeed,
                  retries in 5 minutes after a failure or partial
                  result, and waits a minute if another tab is fetching.
  Could break:    - After a partial refresh, the status shows the new
                    fetch time, even though a failed difficulty may
                    still be using an older live set.
                  - The "Get new questions now" button has no
                    cool-down, so repeated presses can hit the rate
                    limit.

----------------------------------------------------------------------
SECTION: Auto-refresh
----------------------------------------------------------------------

checkQuestionRefresh
  What it does:   Starts a refresh if one is due and this tab isn't
                  already fetching.
  Could break:    Uses the device clock, so changing it can make a
                  refresh early or late.

handleStorageEvent
  What it does:   When another tab saves new questions, loads them into
                  this tab too.
  Could break:    Browsers don't send this event for memory-only
                  storage, so tabs don't share questions when storage is
                  blocked.

startQuestionAutoRefresh
  What it does:   Runs on page load. It registers the status listener
                  first, loads cached questions, fetches if needed, then
                  checks every minute, when the tab becomes visible,
                  when the device reconnects and when another tab
                  saves questions. Calling it again only adds the
                  listener.
  Could break:    There's no way to stop the checks once started.


======================================================================
FILE: script.js
======================================================================

----------------------------------------------------------------------
SECTION: Config
----------------------------------------------------------------------
The leaderboard's storage key. On load it also deletes the old
single-high-score key from earlier versions (through safe storage, so
it can't crash). Game settings now live in game-logic.js.

----------------------------------------------------------------------
SECTION: State
----------------------------------------------------------------------
One object holding everything that changes during a game: the players,
the list of questions, which question is showing, whether it's been
answered, when it appeared, the timer and the last game's settings.

Where it could break:
  - Any code can change it directly; nothing checks it's still valid.

----------------------------------------------------------------------
SECTION: DOM
----------------------------------------------------------------------

$
  What it does:   Looks up a page element by its id.
  Could break:    A renamed or missing id returns null, and the crash
                  happens later with a vague message.

----------------------------------------------------------------------
SECTION: Helpers
----------------------------------------------------------------------

showScreen
  What it does:   Shows one screen (setup, quiz or results) and
                  scrolls to the top.
  Could break:    A misspelled screen name crashes.

escapeHTML
  What it does:   Makes text safe to show inside the page.
  Could break:    Not safe for HTML attribute values if ever reused
                  there.

showSetupError
  What it does:   Shows a message on the setup screen, or hides it when
                  given an empty message.
  Could break:    No known issues.

----------------------------------------------------------------------
SECTION: Leaderboard
----------------------------------------------------------------------

getLeaderboard
  What it does:   Reads the leaderboard through safe storage, dropping
                  damaged entries, sorted best first.
  Could break:    No known issues.

addToLeaderboard
  What it does:   Adds a game's scores, keeps the top 5 and saves.
                  Reports the new entries that made it and whether the
                  save was permanent.
  Could break:    No known crash paths; a failed save is reported on
                  the results screen.

renderLeaderboard
  What it does:   Draws the leaderboard with ranks, names, game length,
                  dates and a NEW tag on just-added scores. It can draw
                  a given list, so results show even if saving failed.
  Could break:    A wrong list id crashes. Dates follow each viewer's
                  local format.

renderStorageNote
  What it does:   Shows a note under the setup leaderboard when the
                  browser won't save anything.
  Could break:    See persistent in storage.js: a full (but not
                  blocked) storage isn't caught here.

----------------------------------------------------------------------
SECTION: Setup
----------------------------------------------------------------------

readSettings
  What it does:   Reads the player count, game length and names. Blank
                  names become "Player 1" and "Player 2".
  Could break:    Crashes if no option is selected (only possible if
                  the HTML changes). Duplicate names aren't prevented.

startGame
  What it does:   Builds the question list (topping up or shortening as
                  needed), resets the players and shows the first
                  question. If no game can be built, it returns to setup
                  with an error message instead of crashing.
  Could break:    Attaching it directly to a button (without the
                  current wrapper) would pass the click in as the
                  settings.

----------------------------------------------------------------------
SECTION: Quiz
----------------------------------------------------------------------

renderScoreboard
  What it does:   Draws each player's name and score and outlines whose
                  turn it is.
  Could break:    No known issues.

renderQuestion
  What it does:   Shows the current question: progress, difficulty
                  badge, whose turn it is, category, question and A-D
                  buttons. Then starts the timer.
  Could break:    No known crash paths, since buildQueue now never
                  leaves an empty slot.

getTimeLeft
  What it does:   Seconds left on the current question, from the real
                  clock.
  Could break:    No known issues.

startTimer
  What it does:   Records when the question appeared and starts
                  updating the timer display every 0.1 seconds.
  Could break:    In a background tab the display updates less often,
                  but the time itself stays correct.

tickTimer
  What it does:   One timer update: redraws the bar and ends the
                  question when time is up.
  Could break:    No known issues.

stopTimer
  What it does:   Stops the timer display.
  Could break:    No known issues.

updateTimerBar
  What it does:   Sets the timer bar's width and colour for the given
                  time left.
  Could break:    Looks up the bar element on every update; harmless
                  but wasteful.

handleAnswer
  What it does:   Handles an answer or a timeout. It scores the answer
                  with the game-logic functions, updates the player,
                  then hands off to showAnswerFeedback. A second call
                  for the same question is ignored.
  Could break:    Everything depends on the "already answered" flag
                  being reset only in renderQuestion.

showAnswerFeedback
  What it does:   Display only: locks the buttons, colours the right
                  and wrong answers, shows the message, updates the
                  scoreboard and reveals Next.
  Could break:    Older Safari ignores the smooth-scroll option, so
                  Next may not scroll into view there.

isGameOver
  What it does:   True once every question has been played.
  Could break:    No known issues.

nextQuestion
  What it does:   Moves to the next question or to the results.
  Could break:    Doesn't check that the question was answered; a new
                  way of calling it could skip questions.

----------------------------------------------------------------------
SECTION: Results
----------------------------------------------------------------------

showResults
  What it does:   Ends the game: saves the scores, picks the title,
                  shows each player's score, accuracy and results by
                  difficulty, and draws the leaderboard. Results always
                  appear; a note explains if scores couldn't be saved.
  Could break:    No known crash paths.

----------------------------------------------------------------------
SECTION: Events
----------------------------------------------------------------------
Connects the page to the game: the player-count options, the Start,
Next, Play Again, Main Menu and Clear leaderboard buttons, closing the
phone keyboard with Enter, the A-D and 1-4 shortcuts, and updating the
timer straight away when the player returns to the tab.

Where it could break:
  - The shortcuts don't ignore modifier keys, so Ctrl+1 also answers.
  - Some in-app browsers block confirm(), so Clear leaderboard does
    nothing there.

----------------------------------------------------------------------
SECTION: Question source status
----------------------------------------------------------------------

formatMinutes
  What it does:   Turns a length of time into text like "12 min".
  Could break:    Negative times show as "less than a minute".

renderQuestionStatus
  What it does:   Updates the status line: fetching, live (fully or
                  partly updated), offline, failed or built-in. It
                  disables "Get new questions now" while fetching.
  Could break:    Reads the shared status directly instead of the copy
                  it's given.

----------------------------------------------------------------------
SECTION: Startup
----------------------------------------------------------------------
Shows the saved leaderboard, warns if storage is unavailable, and
starts the live questions with the status line already registered.


======================================================================
REMAINING RISKS
======================================================================
The six highest risks from the earlier version (storage errors, stuck
requests, the tick-counting timer, running out of questions, rate
limits across tabs, and all-or-nothing refreshes) are fixed and covered
by tests. The biggest remaining ones are:

1. Rate limits across devices
   Where:  withRefreshLock, refreshQuestions
   Effect: Players on one network but in different browsers or devices
           can still block each other, and fall back to built-in
           questions until a retry works.

2. No cool-down on "Get new questions now"
   Where:  refreshQuestions (button handler)
   Effect: Repeated presses can trigger the API's rate limit.

3. Games can be shortened silently
   Where:  buildQueue
   Effect: Players aren't told if there weren't enough questions for
           the chosen length.

4. Storage that fills up after page load
   Where:  createSafeStorage, renderStorageNote
   Effect: The setup screen doesn't warn; only the results screen does.

5. Keyboard shortcuts ignore modifier keys
   Where:  Events
   Effect: Browser shortcuts like Ctrl+1 also answer a question.

6. One leaderboard for all game lengths
   Where:  mergeLeaderboard
   Effect: Long-game scores crowd out Short and Standard ones.
