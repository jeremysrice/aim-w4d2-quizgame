QUIZ CLASH: CODE ANNOTATIONS
============================

These are notes on every JavaScript function Claude generated for the
Quiz Clash mini-app. For each function:

  DOES    what it does
  INPUT   what it expects to receive (and what it returns)
  CHANGE  what I would change, and why

The code is in four files:

  storage.js      safe wrapper around browser storage (1 function that
                  builds 4 tools)
  game-logic.js   the game's rules, with no page code (14 functions)
  trivia-api.js   live questions from the Open Trivia Database
                  (16 functions)
  script.js       page and display code (24 functions including $, plus
                  button and keyboard handlers)

questions.js holds only question data and has no functions. The tests
in tests/ aren't annotated here.

These notes describe the code after the six high-risk fixes. Where a
fix answered an earlier suggestion, the entry says so.

A note on terms:
  - "Storage" means the browser's localStorage, which keeps small
    amounts of data on the player's device between visits.
  - "Element" means a part of the page, such as a button or text box.
  - "Rendering" means drawing or updating part of the page.
  - A "promise" is JavaScript's way of representing something that
    finishes later, such as a network request.


######################################################################
FILE: storage.js
######################################################################

----------------------------------------------------------------------
createSafeStorage
----------------------------------------------------------------------
DOES    Builds the storage wrapper the app uses for all saved data. It
        tests the real storage once by writing and removing a test key.
        If that fails, everything is kept in memory instead. The
        wrapper has four parts:
          get(key, fallback)  reads a saved value, or returns fallback
                              if it's missing or corrupted
          set(key, value)     saves a value; returns true if saved
                              permanently, false if kept in memory only
          remove(key)         deletes a value
          persistent          true if saved data survives closing the
                              page

INPUT   getBackend (function): returns the real storage object,
        normally localStorage. It's a function because in some browsers
        just touching localStorage throws an error when it's blocked.
        Returns the wrapper.

CHANGE  - Re-check persistent after a failed write, so the setup screen
          can warn when storage fills up during a visit, not just when
          it's blocked from the start.
        - Offer a way to clear only the app's own keys.

----------------------------------------------------------------------
safeStorage
----------------------------------------------------------------------
DOES    The single shared wrapper the whole app uses, created by
        createSafeStorage and backed by localStorage when available.

INPUT   None. It's created once when the page loads.

CHANGE  Nothing needed. The earlier suggestion of "one safe helper used
        everywhere" is what this is.


######################################################################
FILE: game-logic.js
######################################################################

----------------------------------------------------------------------
shuffle
----------------------------------------------------------------------
DOES    Returns a new list with the same items in random order, using
        the Fisher-Yates method. The original list isn't changed.

INPUT   arr (list): items to shuffle.
        random (function, optional): returns a number from 0 to just
          under 1. Defaults to Math.random. Tests pass a predictable
          one so the order is the same every run.
        Returns a new shuffled list.

CHANGE  Nothing needed. The earlier suggestion (accept a seeded random
        function) is done.

----------------------------------------------------------------------
makeId
----------------------------------------------------------------------
DOES    Creates a unique id for a leaderboard entry. It uses the
        browser's crypto.randomUUID where allowed (https pages and
        localhost), and the time plus a random string elsewhere.

INPUT   None.
        Returns the id (text).

CHANGE  Nothing needed for a 5-entry leaderboard.

----------------------------------------------------------------------
isValidQuestion
----------------------------------------------------------------------
DOES    Checks a question is safe to play: it has text, 2-4 non-empty
        choices with no repeats (ignoring case and spaces), and a
        correct-answer position that exists.

INPUT   item: a question with q (text), choices (list of text) and
        answer (the position of the correct choice).
        Returns true or false.

CHANGE  Return the reason a question was rejected, such as "duplicate
        choices", so the logs can say why live questions were skipped.

----------------------------------------------------------------------
buildQueue
----------------------------------------------------------------------
DOES    Builds the list of questions for one game. It skips broken
        questions, tops up a short difficulty from the backup
        questions, and shortens the game evenly if there still aren't
        enough. Each player gets their own questions, easy to hard. The
        choices are shuffled by position, so the correct answer is
        always tracked exactly. In two-player games, turns alternate.

INPUT   bank: easy, medium and hard lists of questions.
        playerCount (number): 1 or 2.
        perDifficulty (number): questions per difficulty for each
          player (2, 3 or 4).
        options (optional): fallbackBank (backup questions) and random
          (for tests).
        Returns the queue (the questions in play order) and
        perDifficulty (how many were actually used). Throws an error
        only if it can't give every player at least one question per
        difficulty.

CHANGE  - Tell the player when the game was shortened, for example
          "Only 2 questions per level were available."
        - Avoid repeating questions the player saw in recent games.

----------------------------------------------------------------------
timeRemaining
----------------------------------------------------------------------
DOES    Works out the seconds left on a question from the real time
        that has passed since it appeared, kept between 0 and the time
        limit. This replaced counting timer ticks, which background
        tabs could slow down.

INPUT   startedAtMs (number): when the question appeared.
        nowMs (number): the current time, from the same clock.
        limit (number, optional): defaults to TIME_LIMIT.
        Returns the seconds left.

CHANGE  Nothing needed.

----------------------------------------------------------------------
calculatePoints
----------------------------------------------------------------------
DOES    Works out the points for a correct answer: the difficulty's
        base points plus a speed bonus of up to +50%. An unknown
        difficulty scores 0 (not NaN), and the time left is kept in
        range.

INPUT   difficulty (text): "easy", "medium" or "hard".
        timeLeft (number): seconds left.
        Returns base, bonus and total.

CHANGE  Nothing needed. It's free of side effects and fully tested.

----------------------------------------------------------------------
scoreAnswer
----------------------------------------------------------------------
DOES    Scores one answer: whether it was correct, whether it timed
        out, and the points earned. An answer that arrives after time
        ran out counts as a timeout.

INPUT   item: the question (needs answer and difficulty).
        choiceIndex (number or nothing): 0-3, or null for a timeout.
        timeLeft (number): seconds left when the answer arrived.
        Returns isCorrect, timedOut, base, bonus and total.

CHANGE  Nothing needed.

----------------------------------------------------------------------
createPlayer
----------------------------------------------------------------------
DOES    Creates a player with a zero score and empty stats for each
        difficulty.

INPUT   name (text).
        Returns the new player.

CHANGE  Nothing needed.

----------------------------------------------------------------------
applyAnswer
----------------------------------------------------------------------
DOES    Returns an updated copy of a player after one answer: new
        score, correct count and per-difficulty stats. The original
        player isn't changed.

INPUT   player: a player made by createPlayer.
        difficulty (text): the question's difficulty.
        outcome: the result from scoreAnswer.
        Returns the updated player.

CHANGE  Nothing needed.

----------------------------------------------------------------------
accuracy
----------------------------------------------------------------------
DOES    Returns the percentage of answered questions a player got right
        (0 if they answered none).

INPUT   player.
        Returns a whole number from 0 to 100.

CHANGE  Nothing needed.

----------------------------------------------------------------------
decideResult
----------------------------------------------------------------------
DOES    Picks the results title and the winner(s). For one player:
        "New High Score!", "You Made the Leaderboard!" or "Quiz
        Complete!". For two or more: "<name> Wins!" or "It's a Tie!".

INPUT   players (list).
        options: prevTopScore (the leaderboard's top score before this
          game) and madeBoard (whether a score made the Top 5).
        Returns title (text) and winners (list of player positions).

CHANGE  Name the tied players in the title ("Ann and Bo tie!") if the
        game ever allows more than two players.

----------------------------------------------------------------------
isValidEntry
----------------------------------------------------------------------
DOES    Checks a saved leaderboard entry has a text id and name, a
        positive score and a date.

INPUT   e: one saved entry.
        Returns true or false.

CHANGE  Nothing needed.

----------------------------------------------------------------------
sortBoard
----------------------------------------------------------------------
DOES    Returns a sorted copy of the leaderboard: highest score first,
        and on a tie the more recent score ranks higher.

INPUT   board (list of entries).
        Returns a new sorted list; the original isn't changed.

CHANGE  Nothing needed. The earlier suggestion (return a copy) is done.

----------------------------------------------------------------------
mergeLeaderboard
----------------------------------------------------------------------
DOES    Adds a game's scores to the leaderboard. It ignores zero
        scores, drops damaged old entries, keeps the top 5, and reports
        which new entries made it. New entries get a unique id and the
        real time as their date.

INPUT   board (list): the current entries.
        entries (list): one per player, with name, score and length.
        options (optional): now, idFn and size, so tests can control
          the time, the ids and the board size.
        Returns board (the new top 5) and newIds (ids of new entries
        that made it).

CHANGE  Keep a separate board for each game length. A Long game can
        score about twice what a Short game can, so one shared board
        isn't fair.

FILE: trivia-api.js
######################################################################

----------------------------------------------------------------------
wait
----------------------------------------------------------------------
DOES    Pauses for a given time, to space out API requests.

INPUT   ms (number): milliseconds to wait.
        Returns a promise that finishes after that time.

CHANGE  Nothing needed.

----------------------------------------------------------------------
notifyQuestionListeners
----------------------------------------------------------------------
DOES    Calls every registered function with the current question
        status. Each runs separately, so one failing can't stop the
        rest.

INPUT   None.
        Returns nothing.

CHANGE  Nothing needed. The earlier suggestion (isolate each listener)
        is done.

----------------------------------------------------------------------
onQuestionSourceChange
----------------------------------------------------------------------
DOES    Registers a function to call when the question status changes.
        Registering the same function twice has no effect.

INPUT   fn (function): called with the status object.
        Returns nothing.

CHANGE  Return a way to unregister the function.

----------------------------------------------------------------------
getActiveBank
----------------------------------------------------------------------
DOES    Returns the questions the next game should use: the live list
        for each difficulty that has one, otherwise the built-in list.
        buildQueue tops up any difficulty that's still short.

INPUT   None.
        Returns easy, medium and hard lists of questions.

CHANGE  Nothing needed. Topping up now happens in one place
        (buildQueue), with random backup questions rather than always
        the first few.

----------------------------------------------------------------------
loadQuestionCache
----------------------------------------------------------------------
DOES    Loads saved questions when the page opens, or when another tab
        saves new ones. It ignores and deletes caches that are
        corrupted, from an older version, dated in the future, or have
        no playable questions.

INPUT   None. It reads storage.
        Returns true if usable questions were loaded.

CHANGE  Nothing needed. The earlier suggestions (cache version number,
        checking each question, treating future dates as stale) are
        done.

----------------------------------------------------------------------
saveQuestionCache
----------------------------------------------------------------------
DOES    Saves the live questions, when they were fetched, and whether
        the fetch was partial. If storage is full or blocked it only
        logs a warning, because the questions are already in use.

INPUT   None.
        Returns true if saved.

CHANGE  Nothing needed. A failed save is no longer reported as a failed
        refresh.

----------------------------------------------------------------------
normalizeApiQuestion
----------------------------------------------------------------------
DOES    Converts one question from the API into the game's format:
        q, choices (the correct one first), answer (always 0, because
        buildQueue shuffles) and category. It decodes the API's
        URL-encoded text and shortens names like "Entertainment: Film"
        to "Film". Returns nothing for a question that can't be decoded
        or isn't playable.

INPUT   item: one API question with question, correct_answer,
        incorrect_answers and category, all URL-encoded.
        Returns the converted question, or null.

CHANGE  Count the questions it skips and report the count in the
        logs.

----------------------------------------------------------------------
fetchJsonWithTimeout
----------------------------------------------------------------------
DOES    Fetches a web address and reads the reply, cancelling if it
        takes longer than the timeout. The timeout covers reading the
        reply as well as waiting for it.

INPUT   url (text): the address to fetch.
        ms (number): the timeout in milliseconds.
        Returns a promise of ok (true or false), status (the HTTP
        code) and data (the parsed reply, or null).

CHANGE  Nothing needed.

----------------------------------------------------------------------
fetchDifficulty
----------------------------------------------------------------------
DOES    Fetches 20 multiple-choice questions of one difficulty. When
        rate-limited, it waits (5.5 seconds, then 11) and retries, up
        to 3 attempts in total. A timeout or other error fails that
        difficulty.

INPUT   difficulty (text): "easy", "medium" or "hard".
        attempt (number, optional): used internally for retries.
        Returns a promise of a list of questions.

CHANGE  Use the API's session tokens so new sets don't repeat
        questions the player has already seen.

----------------------------------------------------------------------
fetchAllDifficulties
----------------------------------------------------------------------
DOES    Fetches easy, medium and hard in turn, 5.5 seconds apart,
        asking the API one level easier (easy and medium use its
        "easy", hard uses its "medium"; see apiDifficulty in the
        config). Questions already fetched for an earlier level are
        dropped so none repeat. A failure on one doesn't stop the
        others.

INPUT   None.
        Returns a promise of fetched (the questions that arrived, by
        difficulty) and failed (the difficulties that didn't).

CHANGE  Nothing needed.

----------------------------------------------------------------------
withRefreshLock
----------------------------------------------------------------------
DOES    Uses the browser's Web Locks API so only one tab fetches at a
        time. It runs the fetch without a lock in browsers without Web
        Locks, on pages opened from disk (where Chrome's lock request
        never answers), or if the lock request throws.

INPUT   task (function): the work to do while holding the lock.
        Returns a promise of true if the task ran, or false if another
        tab already holds the lock.

CHANGE  Coordinate across devices too, through a small shared server
        cache of questions. That's the only way to stop players on one
        network from sharing the API's rate limit.

----------------------------------------------------------------------
manualRefreshWaitMs
----------------------------------------------------------------------
DOES    Says how long until "Get new questions now" works again. The
        button has a 1-minute cool-down after each press so repeated
        presses can't hit the API's rate limit.

INPUT   now (number, optional): the current time in ms. Defaults to
        Date.now().
        Returns the wait in ms, or 0 if the button is ready.

CHANGE  Share the cool-down between tabs through storage, so pressing
        the button in several tabs can't get around it.

----------------------------------------------------------------------
refreshQuestions
----------------------------------------------------------------------
DOES    Fetches a fresh set of questions and makes it the active set.
        Only one tab fetches at a time. Unless forced, it first uses
        another tab's fresh questions if there are any. It keeps any
        difficulties that succeed, and retries in 5 minutes after a
        failure or partial result. A failed level keeps its previous
        live set, minus any question that's now in a new set. If
        another tab is fetching, it waits a minute. A forced refresh
        is ignored during the button's 1-minute cool-down; automatic
        refreshes aren't affected.

INPUT   options (optional): force (true or false). The "Get new
        questions now" button passes true to skip the freshness check
        (and start the cool-down).
        Returns a promise that finishes when done. It handles its own
        errors.

CHANGE  Record a fetch time for each difficulty, so the status line
        is accurate after a partial refresh.

----------------------------------------------------------------------
checkQuestionRefresh
----------------------------------------------------------------------
DOES    Starts a refresh if one is due and this tab isn't already
        fetching.

INPUT   None.
        Returns nothing.

CHANGE  Nothing needed.

----------------------------------------------------------------------
handleStorageEvent
----------------------------------------------------------------------
DOES    When another tab saves new questions to storage, loads them
        into this tab too.

INPUT   event: the browser's storage event (it reads event.key).
        Returns nothing.

CHANGE  Use a BroadcastChannel as well, so tabs can still share
        questions when storage is blocked and the storage event never
        fires.

----------------------------------------------------------------------
startQuestionAutoRefresh
----------------------------------------------------------------------
DOES    Runs on page load. It registers the status listener first, then
        loads cached questions and fetches if needed. After that it
        checks every minute, when the tab becomes visible, when the
        device reconnects, and when another tab saves questions.
        Calling it again only adds the listener.

INPUT   onChange (function, optional): the listener to register first.
        Returns nothing.

CHANGE  Return a stop function that removes the timer and listeners.

FILE: script.js

----------------------------------------------------------------------
$
----------------------------------------------------------------------
DOES    Finds a page element by its id.

INPUT   id (text).
        Returns the element, or null if none has that id.

CHANGE  Raise a clear error naming the missing id, so a typo is easy

----------------------------------------------------------------------
showScreen
----------------------------------------------------------------------
DOES    Hides all screens, shows the requested one and scrolls to the
        top.

INPUT   name (text): "setup", "quiz" or "results".
        Returns nothing.

CHANGE  Move keyboard focus to the new screen's heading, so screen
        reader and keyboard users know the screen changed.

----------------------------------------------------------------------
escapeHTML
----------------------------------------------------------------------
DOES    Turns text into HTML-safe text, so names and answers can't add
        their own HTML to the page.

INPUT   str (text).
        Returns the escaped text.

CHANGE  Build the leaderboard, scoreboard and results with page
        elements and textContent instead of HTML strings. Then no
        escaping is needed.

----------------------------------------------------------------------
showSetupError
----------------------------------------------------------------------
DOES    Shows a message on the setup screen, or hides it when the
        message is empty. Used when a game can't be built.

INPUT   message (text).
        Returns nothing.

CHANGE  Nothing needed.

----------------------------------------------------------------------
getLeaderboard
----------------------------------------------------------------------
DOES    Reads the leaderboard through safeStorage, drops damaged
        entries, and returns it sorted best first.

INPUT   None.
        Returns a list of entries.

CHANGE  Nothing needed. The earlier suggestion (check each entry) is
        done.

----------------------------------------------------------------------
addToLeaderboard
----------------------------------------------------------------------
DOES    Adds a game's scores with mergeLeaderboard and saves the result
        through safeStorage.

INPUT   entries (list): one per player, with name, score and length.
        Returns board (the new top 5), newIds (entries that made it)
        and saved (false if the scores couldn't be saved permanently).

CHANGE  Nothing needed. A failed save no longer stops the results
        screen.

----------------------------------------------------------------------
renderLeaderboard
----------------------------------------------------------------------
DOES    Draws the leaderboard: rank, name, game length, date and score,
        with a NEW tag on entries just added. It shows "No scores yet"
        when empty.

INPUT   listId (text): "leaderboard-setup" or "leaderboard-results".
        highlightIds (list, optional): ids to tag NEW.
        board (list, optional): the entries to draw. Defaults to the
          saved leaderboard.
        Returns nothing.

CHANGE  Announce a new placing to screen readers, such as "You placed
        2nd".

----------------------------------------------------------------------
renderStorageNote
----------------------------------------------------------------------
DOES    Shows a note under the setup leaderboard when the browser won't
        let the game save anything.

INPUT   None.
        Returns nothing.

CHANGE  Also show it after a save fails because storage is full (see
        createSafeStorage).

----------------------------------------------------------------------
readSettings
----------------------------------------------------------------------
DOES    Reads the setup screen: number of players, game length and
        names. Blank names become "Player 1" and "Player 2".

INPUT   None.
        Returns playerCount, length and names.

CHANGE  - Stop players giving themselves the same name.
        - Remember the last names and settings for returning players.

----------------------------------------------------------------------
startGame
----------------------------------------------------------------------
DOES    Starts a new game. It builds the question list with buildQueue
        (topping up or shortening as needed), creates the players, and
        shows the first question. If no game can be built, it returns to
        setup with an error message.

INPUT   settings (optional): playerCount, length and names. If left
        out, it reads the setup form. Play Again passes the last
        game's settings.
        Returns nothing.

CHANGE  Make settings required, and have the Start button call
        startGame(readSettings()), so the click event can never be
        mistaken for settings.

----------------------------------------------------------------------
renderScoreboard
----------------------------------------------------------------------
DOES    Draws each player's name and score and outlines whose turn it
        is.

INPUT   None.
        Returns nothing.

CHANGE  Build the score cards once per game and only update the numbers
        afterwards.

----------------------------------------------------------------------
renderQuestion
----------------------------------------------------------------------
DOES    Shows the current question: progress, difficulty badge, whose
        turn it is, category, question and A-D buttons. It clears the
        last feedback and starts the timer.

INPUT   None.
        Returns nothing.

CHANGE  Split it into smaller pieces (progress, badge, turn banner,
        answers).

----------------------------------------------------------------------
getTimeLeft
----------------------------------------------------------------------
DOES    Returns the seconds left on the current question, using
        timeRemaining and the real clock.

INPUT   None.
        Returns the seconds left.

CHANGE  Nothing needed.

----------------------------------------------------------------------
startTimer
----------------------------------------------------------------------
DOES    Records when the question appeared and starts updating the
        timer display every 0.1 seconds.

INPUT   None.
        Returns nothing.

CHANGE  Animate the bar with requestAnimationFrame for smoother
        movement. The timing itself is already correct.

----------------------------------------------------------------------
tickTimer
----------------------------------------------------------------------
DOES    One timer update: redraws the bar from the real time left, and
        treats the question as timed out when it reaches zero.

INPUT   None.
        Returns nothing.

CHANGE  Nothing needed.

----------------------------------------------------------------------
stopTimer
----------------------------------------------------------------------
DOES    Stops the timer display.

INPUT   None.
        Returns nothing.

CHANGE  Nothing needed.

----------------------------------------------------------------------
updateTimerBar
----------------------------------------------------------------------
DOES    Sets the timer bar's width and colour for the time left: green

INPUT   timeLeft (number): seconds left.
        Returns nothing.

CHANGE  Look up the bar once instead of on every update, and show a
        number countdown for players who can't tell the colours apart.

----------------------------------------------------------------------
handleAnswer
----------------------------------------------------------------------
DOES    Handles an answer or a timeout. It stops the timer, scores the
        answer with scoreAnswer and applyAnswer (game-logic.js), and
        hands off to showAnswerFeedback. A second call for the same
        question is ignored, and so is an answer that doesn't exist on
        the question (like D on a 2-choice question).

INPUT   choiceIndex (number or nothing): 0-3 for A-D, or null when
        time runs out. Anything outside the question's choices is
        ignored.
        Returns nothing.

CHANGE  Nothing needed. The earlier suggestion (separate scoring from
        display) is done.

----------------------------------------------------------------------
showAnswerFeedback
----------------------------------------------------------------------
DOES    Display only: locks the buttons, colours the correct answer
        green and a wrong pick red, shows the message, updates the
        scoreboard and reveals Next (or See Results).

INPUT   item: the question.
        choiceIndex (number or nothing): what the player picked.
        outcome: the result from scoreAnswer.
        Returns nothing.

CHANGE  Pause briefly before showing Next, so fast tappers see the
        answer before moving on.

----------------------------------------------------------------------
isGameOver
----------------------------------------------------------------------
DOES    Returns true once every question has been played.

INPUT   None.
        Returns true or false.

CHANGE  Nothing needed.

----------------------------------------------------------------------
nextQuestion
----------------------------------------------------------------------
DOES    Moves to the next question, or to the results after the last
        one.

INPUT   None. (The Next button passes its click event, which is

CHANGE  Do nothing unless the current question has been answered.

----------------------------------------------------------------------
showResults
----------------------------------------------------------------------
DOES    Ends the game. It saves the scores, picks the title with
        decideResult, shows each player's score, accuracy and results
        by difficulty, and draws the leaderboard. Results always
        appear; a note explains if scores couldn't be saved.

INPUT   None. It reads the finished game.
        Returns nothing.

CHANGE  Nothing needed. The earlier suggestions (results first, any
        number of players, one source of truth for the title) are done.

----------------------------------------------------------------------
formatMinutes
----------------------------------------------------------------------
DOES    Turns a length of time into text like "12 min" or "less than a
        minute".

INPUT   ms (number): milliseconds.
        Returns the text.

CHANGE  Use the browser's Intl.RelativeTimeFormat for properly
        translated phrases that also handle hours.

----------------------------------------------------------------------
renderQuestionStatus
----------------------------------------------------------------------
DOES    Updates the status line: fetching, live (fully or partly
        updated), offline, failed or built-in. It disables "Get new
        questions now" while this tab is fetching and during its

        Returns nothing.

CHANGE  Use the status object it's given, and say when another tab is

======================================================================
BUTTON AND KEYBOARD HANDLERS (script.js)
======================================================================
These short functions connect the page to the game. In the code they
are unnamed functions attached with addEventListener, so each one is
labelled below by the element it listens to and the event that
triggers it. Every handler receives the browser's event for its action
(a click, change or key press); most of them ignore it.

----------------------------------------------------------------------
HANDLER: Player count options (change)
----------------------------------------------------------------------
LISTENS TO  The "1 Player" and "2 Players" options on the setup screen.

DOES    Shows the Player 2 name box for "2 Players" and hides it for
        "1 Player".

INPUT   A change event. It ignores the event and calls readSettings.

CHANGE  Read the choice from the event (event.target.value) instead of
        re-reading the whole form.

----------------------------------------------------------------------
HANDLER: Start Game button (click)
----------------------------------------------------------------------
LISTENS TO  The Start Game button (id "start-btn").

DOES    Starts a new game from the setup form by calling startGame.

INPUT   A click event, deliberately not passed to startGame.

CHANGE  Call startGame(readSettings()) explicitly (see startGame).

----------------------------------------------------------------------
HANDLER: Player name boxes (keydown)
----------------------------------------------------------------------
LISTENS TO  The Player 1 and Player 2 name boxes.

DOES    When Enter (or "done" on a phone) is pressed, closes the phone
        keyboard.

INPUT   A keydown event. It checks event.key for "Enter".

CHANGE  Wrap the setup controls in a form, so Enter also starts the
        game.

----------------------------------------------------------------------
HANDLER: Answer buttons A-D (click)
----------------------------------------------------------------------
LISTENS TO  Each answer button. A new handler is created for every
            button each time renderQuestion draws a question.

DOES    Calls handleAnswer with that button's position (0 for A, 1 for
        B, and so on).

INPUT   A click event, which it ignores.

CHANGE  Use one click handler on the answers container instead of four
        new ones per question.

----------------------------------------------------------------------
HANDLER: Next button (click)
----------------------------------------------------------------------
LISTENS TO  The Next / See Results button (id "next-btn").

DOES    Calls nextQuestion.

INPUT   A click event, which nextQuestion receives and ignores.

CHANGE  Wrap it so nextQuestion isn't handed the event.

----------------------------------------------------------------------
HANDLER: Play Again button (click)
----------------------------------------------------------------------
LISTENS TO  The Play Again button (id "replay-btn").

DOES    Starts a new game with the same players and length, using the
        current questions.

INPUT   A click event, which it ignores.

CHANGE  Nothing needed.

----------------------------------------------------------------------
HANDLER: Main Menu button (click)
----------------------------------------------------------------------
LISTENS TO  The Main Menu button (id "menu-btn").

DOES    Redraws the setup leaderboard, then shows the setup screen.

INPUT   A click event, which it ignores.

CHANGE  Have the leaderboard redraw itself whenever scores are saved.

----------------------------------------------------------------------
HANDLER: Clear leaderboard link (click)
----------------------------------------------------------------------
LISTENS TO  The "Clear leaderboard" link (id "clear-lb-btn").

DOES    Asks for confirmation, then deletes the saved scores through
        safeStorage and redraws the empty leaderboard.

INPUT   A click event, which it ignores.

CHANGE  Use a confirmation inside the page instead of confirm(), which
        some in-app browsers block.

----------------------------------------------------------------------
HANDLER: Keyboard shortcuts (keydown on the whole page)
----------------------------------------------------------------------
LISTENS TO  Every key press on the page.

DOES    While a question is waiting for an answer, A-D or 1-4 answers
        it. Key presses with Ctrl, Alt or Cmd held are ignored, so
        browser shortcuts like Ctrl+1 don't also answer, and so is a
        held-down key. A letter or number with no matching choice is
        ignored too. (Enter for Next works because the Next button has
        focus.)

INPUT   A keydown event. It reads event.key, the modifier keys and
        event.repeat.

CHANGE  Show the shortcuts on screen.

----------------------------------------------------------------------
HANDLER: Returning to the tab (visibilitychange)
----------------------------------------------------------------------
LISTENS TO  The page becoming visible again after the player switched
            tabs or apps.

DOES    During a question, updates the timer straight away. Because
        the timer uses the real clock, a question whose time ran out
        while the tab was hidden is marked "Time's up" immediately.

INPUT   A visibilitychange event, which it ignores; it checks
        document.hidden.

CHANGE  Nothing needed.

----------------------------------------------------------------------
HANDLER: Get new questions now button (click)
----------------------------------------------------------------------
LISTENS TO  The "Get new questions now" button (id
            "refresh-questions-btn").

DOES    Starts a forced refresh with refreshQuestions({ force: true }),
        skipping the check for another tab's fresh questions. The
        button is disabled while this tab is fetching and for 1 minute
        after each press, with a countdown on the button.

INPUT   A click event, which it ignores.

CHANGE  Nothing needed.


######################################################################
SUMMARY
######################################################################

DONE: the six changes previously listed as "do first"
  1. Safe storage everywhere (storage.js).
